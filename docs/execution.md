# 投递方式与运行配置

[返回 README](../README.md)

## 队列与直接发送

在后台「设置」选择投递方式，默认使用队列：

| 方式 | 即时消息 | 定时与重试 | 适用情况 |
| --- | --- | --- | --- |
| 队列（`queue`） | 按目标渠道入队，由消费者发送 | 12 小时内通过延迟队列，较远的定时消息由 Cron 在进入窗口后入队 | 多渠道扇出、持续投递或需要更细重试间隔 |
| 直接发送（`direct`） | 在请求后台发送，每次最多处理 4 个目标 | 其余投递、定时和重试交给每分钟 Cron，每轮最多处理 4 个到期目标 | 投递较少，希望不配置 Queues |

未轮到的投递不消耗尝试次数，但积压会增加延迟。`sendAt` 是计划时间，不是精确送达承诺。

不使用 Queues 时，删除 `wrangler.jsonc` 中整个 `queues` 配置段，运行 `pnpm cf-typegen` 后部署，并在后台选择「直接发送」。若配置仍为队列但缺少绑定，运行时会降级为直接发送并记录警告。入队失败的投递留待下一轮 Cron 补偿。

## 重试与恢复

每个渠道独立投递，失败不会阻止其他渠道完成。网络错误、10 秒请求超时、HTTP 408、429、5xx 等错误可自动重试；其他 4xx 及渠道业务错误按适配器分类处理。

退避间隔依次为 10 秒、30 秒、2 分钟、10 分钟、30 分钟、1 小时，此后保持 1 小时。上游返回有效的 `Retry-After` 或渠道重试提示时优先使用，限制在 1 秒至 1 小时。直接发送方式仍由每分钟 Cron 派发，因此实际间隔可能更长。

每分钟的 Cron 也负责恢复长时间未开始或执行失联的投递。重复队列消息按投递 ID 和尝试次数认领，避免同一次尝试被重复执行；上游已受理但本地未能记录结果时，仍可能再次请求。Webhook 接收端可使用 `X-Sender-Delivery` 标识去重。

## 运行设置与保留

设置保存到 D1 后生效，无需重新部署：

| 设置 | 默认值 | 可配置范围 |
| --- | --- | --- |
| 投递方式 | 队列 | 队列、直接发送 |
| 最大尝试次数 | 5 次 | 1 至 10 次，包含首次发送 |
| 消息保留天数 | 30 天 | 1 至 3650 天 |
| 统计保留天数 | 90 天 | 1 至 3650 天 |

每小时清理超过保留期且全部投递已结束的消息。发送时间未到或仍有待处理投递的消息保留，消息删除后其投递记录一并删除，幂等键也随之失效。统计保留独立于消息日志，调大保留天数不会恢复已清理的数据。

统计包含投递成功、失败、重试次数和送达延迟，支持 24 小时、7 天、30 天、90 天范围；较长范围按查看者时区的自然日汇总。

## 后台认证与语言

默认使用 Basic 认证，用户名来自 `wrangler.jsonc` 的 `ADMIN_USERNAME`，默认 `admin`；密码来自 secret `ADMIN_PASSWORD`。

使用 Cloudflare Access 时，在 Zero Trust 中创建保护 `/admin` 及其子路径的 Self-hosted 应用，配置访问策略，并在 `wrangler.jsonc` 的 `vars` 中设置：

| 变量 | 值 |
| --- | --- |
| `ADMIN_AUTH_MODE` | `access` |
| `ACCESS_TEAM_DOMAIN` | 团队域名，如 `myteam.cloudflareaccess.com` |
| `ACCESS_AUD` | 对应应用的 AUD tag |

修改后重新部署。`/api/*` 使用 API Key，避免用后台 Access 策略拦截业务调用。

界面首次访问按浏览器语言选择简体中文或 English，其他语言回退到英文。可通过语言按钮或「设置 › 界面语言」切换，手动选择保存在当前浏览器。切换语言保留未保存的表单内容，不改变渠道名称、消息或已保存的模板文案。

## Cloudflare 用量与费用

Queues 支持 Workers Free 和 Paid。Free 包含每天 10,000 次操作及 24 小时消息保留；正常投递通常涉及写入、读取、删除共 3 次操作。项目按目标渠道分别入队，多渠道扇出、重试和死信队列都会增加操作量。具体额度和计价以 [Queues 官方说明](https://developers.cloudflare.com/queues/platform/pricing/)为准。

Worker 请求、CPU、D1 读写与存储也有各自的额度和计费，后台查询、维护和统计同样产生用量。部署后应观察实际用量，按任务规模和保留时间调整配置，详见 [Workers 价格](https://developers.cloudflare.com/workers/platform/pricing/)和 [D1 价格](https://developers.cloudflare.com/d1/platform/pricing/)。
